# Umbrista Implementation Plan

> Work through the tasks in order. Each task is one branch and one reviewed pull request into
> `develop`. Steps use checkboxes (`- [ ]`) for tracking.

**Goal:** Build Umbrista, an invented night café's full website (cinematic 3D, interactive, real
forms, a staff view with a safe demo), in a professionally run public repository, and launch it on
Vercel as v1.0.0.

**Architecture:** A Vite + React + TypeScript single-page app with lazily loaded routes. One shared
WebGL canvas, driven by React Three Fiber, hosts four 3D moments; GSAP ScrollTrigger and Lenis drive
the scroll journey. Vercel serverless functions (`api/`) validate every write and talk to Neon
Postgres through `pg`; a separate `demo` schema reached only through a separate database role keeps
reviewer data apart from real data. Code shared by the browser and the functions (hours, schemas,
menu) lives in `shared/`.

**Tech Stack:** Vite, React 19, TypeScript, React Router, Three.js, @react-three/fiber,
@react-three/drei, GSAP (ScrollTrigger), Lenis, Motion, zod, pg, bcryptjs, Vitest, Testing Library,
jsdom, Playwright, oxlint, Lighthouse CI, @resvg/resvg-js, Vercel, Neon.

**Spec:** `docs/specs/2026-11-26-umbrista-design.md` (read it before any task).

## Global Constraints

- Everything free. Neon free plan on the owner's personal account; Vercel free (Hobby) plan.
- Approved runtime dependencies, and no others without asking the owner: `react`, `react-dom`,
  `react-router`, `three`, `@react-three/fiber`, `@react-three/drei`, `gsap`, `lenis`, `motion`,
  `zod`, `pg`, `bcryptjs`, and the two `@fontsource` families chosen on the brand board.
- Approved development dependencies: `vite`, `@vitejs/plugin-react`, `typescript`, `@types/*`,
  `vitest`, `@testing-library/react`, `@testing-library/user-event`, `@testing-library/jest-dom`,
  `jsdom`, `@playwright/test`, `oxlint`, `@lhci/cli`, `@resvg/resvg-js`, `@vercel/node`, `tsx`.
- No AI attribution anywhere: no `Co-Authored-By`, no "Generated with", no mention of AI tools or
  assistants in commits, PRs, code, comments or docs. Use the repository's configured git identity.
- Commits: conventional subject, blank line, short `- ` bullets; one concern per commit.
- Branches: `main` (protected, releases only) ← `develop` (integration) ← one branch per task,
  `task/<n>-<slug>`; each task is one PR into `develop`, merged with a merge commit on green, then the
  branch is renamed `merged/task-<n>-<slug>` (never deleted).
- Content Security Policy, sent by `vercel.json` on every route:
  `default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self' data: blob:; font-src 'self'; connect-src 'self'; worker-src 'self' blob:; frame-ancestors 'none'; base-uri 'self'; form-action 'self'`.
  No inline `<script>` or `<style>` and no `style=` attributes in served HTML (JS-set styles are fine).
  No asset of any kind loaded from another origin (drei helpers that fetch from CDNs are not used).
- Original assets only: no stock photos, no downloaded 3D models; any third-party asset must be CC0
  and recorded in `docs/brand.md` with its licence.
- **Higgsfield generation gate.** Never call any Higgsfield generation tool (images, video, 3D, upscale,
  background removal, editing) without the owner's explicit go for that one asset. First propose it:
  what it is, what it is for, where it goes, the prompt or brief, the model, and the estimated credits
  (from Higgsfield's cost-estimate tools, which are free to call). Record each generated asset in
  `docs/brand.md` (what, where used, model, date). Prompts are written carefully against the brand
  board, video is planned shot by shot before anything is generated, and still compositions are
  designed first.
- Candidate generated assets (each still needs its own go): brand-board mood frames (Task 2); rain,
  steam and lamp-glow textures or matcaps for the shaders (Task 7); a night-street environment
  backplate and per-chapter stills (Tasks 8–9); a 3D cup model via Higgsfield 3D as an alternative to
  the code-built lathe cup (Task 9); journal and Story illustrations (Task 12); a short launch teaser
  video for the README and social (Task 19).
- Honesty note on every page and in every confirmation: Umbrista is a design project, not a real café.
- Performance budgets (mobile, throttled): LCP < 2.5 s, CLS < 0.05, Lighthouse performance ≥ 90 on
  `/`, `/menu`, `/visit`. First paint is HTML text; 3D loads after first paint behind a static still.
- Accessibility: WCAG 2.2 AA; every 3D interaction has a non-3D control; menu, hours, address and
  prices are always text; reduced motion turns the journey into still chapters with fades.
- Café hours: open at the fictional city's computed sunset, close at `03:00` city time.
- The scene follows the visitor's local clock; the "See it at night" switch overrides it.
- Rate limits, per visitor (IP, IPv6 grouped by /64): reservations 5/hour, orders 10/hour,
  sign-ups 5/hour, staff sign-in 10 per 15 minutes.
- Retention: reservations and orders deleted 30 days after their night; sign-ups kept until a
  deletion request; staff sessions 7 days; demo sessions 2 hours.
- Data requests only through a GitHub issue; no personal email published.

## Review Focus

1. **Midnight to 03:00.** A visitor reserving or ordering at 01:30 café time is still "tonight"; the
   café night that started yesterday must be used, and a pickup after 03:00 refused (Task 5 tests).
2. **No sunset, or DST change.** Sunset is computed at the city's fixed coordinates, but the visitor's
   dusk estimate can hit a date with a DST shift or an extreme offset; it must still return a time and
   never throw (Task 5 tests).
3. **WebGL lost mid-session.** `webglcontextlost` after load must swap to the still images, not leave
   a black canvas (Task 6 test).
4. **Double submit and flaky network.** Clicking Send twice creates one record; a failed request keeps
   the form filled and says what to do (Task 14 tests, using an idempotency key).
5. **Demo session asking for real records.** A demo session that sends a real record's id to a staff
   action gets 404 and changes nothing (Task 16 test).
